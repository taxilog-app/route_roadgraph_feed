# route_roadgraph_feed — 道路グラフの配信

タクログ（運行ログアプリ）が使う **道路グラフ**（交差点と道路区間）を、営業圏ごとに配る置き場です。

端末は運賃メーターで選んでいる営業圏の**1件だけ**を落とします。
取れなくても、アプリは同梱の福岡ぶんでこれまで通り動きます（配信は上乗せ）。

## 何に使われるか

| 使い道 | これが無いと |
|---|---|
| 走行軌跡の道路スナップ | 線が道に吸い付かず、生のGPSのまま描かれる |
| 抜け道の登録（交差点への磁石スナップ） | 点を置きにくい |
| 交通規制の標識の向き（道への吸着） | 標識が道と平行にならない・反対車線に立つ |
| 交差点名 | 出ない |

## 中身

```
index.json  … 目次（形の版数・営業圏ごとのURL・指紋・件数）
```

🔴 **実物（road_graph.sqlite.gz）はこのリポジトリには入っていません。**
GitHub の「**リリース添付ファイル**」で配っています（目次の `file` が絶対URL）。

| | Pages（この置き場） | リリース添付 |
|---|---|---|
| 大きさの上限 | **サイト全体で1GB** | 1ファイル2GiB・**総量は無制限** |
| 通信量 | 月100GB（ソフト上限） | **無制限** |

2026-08-15 に引っ越しました。45営業圏で 1.10GB となり Pages の1GBを超えたためです。
超えると「大きいファイルだけ弾かれる」のではなく**サイトごと公開が止まる**＝
今届いている営業圏もまとめて届かなくなります。

**作業の順番（この順を守れば、運転手に届かない時間が生まれません）**
```
python3 tools/stage_release_assets.py             # ① 平らな名前で並べる（_assets/）
python3 tools/stage_release_assets.py --print-cmd # ② 🔴社長が gh release create で添付
python3 tools/switch_index_to_release.py data-YYYY-MM   # ③ 目次を添付URLへ向ける（添付が全部在るか確かめてから書き換わる）
python3 tools/verify_index.py --remote            # ④ 本物のURLから落として検査
                                                  # ⑤ 🔴社長が push
```
⚠️ アプリは **v1.11.0 以降**が絶対URLに対応（`sqlite_feed_updater.dart`）。
古いアプリは新しい営業圏を落とせない（＝同梱データのまま静かに動く）。

- **gzipのまま配ります**（福岡で 22.7MB → 7.7MB）。端末側で展開します。
- `sha256` は**配られたまま（圧縮された状態）**の指紋です。端末は展開の前に照合します。

### SQLite の中身

| 表 | 何が入っているか |
|---|---|
| `nodes` | 交差点（`id, lat, lng, name`） |
| `edges` | 交差点どうしをつなぐ道路区間（`id, a, b, name, cls, rank, poly`） |
| `edge_cell` | 引き当てを速くするための格子索引（`cell, eid`） |
| `oneway_way` / `oneway_cell` | 一方通行の線 |

`schema` は**形の版数**です。表や列を増やしたら必ず上げます。
アプリは自分が読める版数と一致した時だけ採用します（古い形を読んで起動できなくなるのを防ぐため）。

⚠️ 仙台の466件も同じ理由（OSM側の登録が469件・道具は99.4%拾えている）。沖縄の51件も同じ（登録58件・88%）。

いずれもOSM側の登録がその件数しか無く、取り込み率は84〜100%。取りこぼしではない。

🔴 **茨城が現在いちばん大きい（配布74.6MB・展開後222.8MB＝アプリの上限96MBの78%）。**
四角に東京東部と千葉北部が入るため。次が尾張・三河（71.1MB・真ん中に名古屋市がまるごと入る）、
千葉（65.6MB・東京23区がまるごと入る）。いずれも隣接する大都市へ日常的に入る営業圏なので
この重なりは無駄ではないが、**上限96MBまでの余裕は2割強しかない**。
アプリの受け取り上限96MB・GitHubの1ファイル上限100MBの内側だが、これ以上大きい営業圏を作るときは
**営業圏の形で切る（3kmの余白つき）か、営業圏を分割する**こと。形で切ると千葉は約48MB・相模は約22MBまで減る（実測）。

以降、主要都市 → 全営業圏の順に増やしていきます（83営業圏中37圏・四国と関東は収録済み）。
⚠️ **東京島しょ地区（伊豆・小笠原諸島）は対象外**＝島ごとに道が独立していて車で行き来できず、
丁目境界も配信キーも存在しない。

🔴 **フォルダ名は「配信キー」を使う**（アプリ側 `PrefsRepository.loadFeedAreaKey()` が引く名前）。
営業圏の正典キーとは3つだけ違う＝東京23区は `tokyo`（正典は tokyo23）・京都市域は `kyoto`（同 kyoto_city）・
埼玉南部は `saitama`（同 saitama_s）。**沖縄本島は `okinawa_main`・広島市域は `hiroshima_city` で正典と同じ**。
読み替え表＝アプリの `_feedAreaAlias` と `tools/dump_area_matrix.py` の `REG_AREA_ALIAS`（両方揃えて直す）。

## 🔴 作るときの注意（2026-08-12 に実際に踏んだもの）

- **2本目のサーバー(kumi.systems)は地図データが数週間〜2か月半遅れていることがある。**
  1本目が混んでいて回されると、取得は成功するのに古いデータが黙って混ざる
  （札幌=6/30版・広島=5/31版を実際に掴んだ）。
  `fetch_osm_area.py` が日付を表示して14日より古ければ警告するようにした。
  出たら空いている時に本家(overpass-api.de)で取り直す。
- **混んでいると「途中まで」を正常な形で返してくる**（`remark` が付く）。
  同じく道具が弾くようにした。放っておくと穴あきの道路グラフが出来る。
- **生成道具の `db.commit()` を消さない。** 消すと「表はあるが1行も入っていない」
  ファイルが出来る。大きさもSQLiteとしての正常さも変わらないので見た目では気づけない。
  `verify_index.py` の検査⑤がこれを弾く。

## 作り方

```
python3 tools/fetch_osm_area.py <minLat> <minLng> <maxLat> <maxLng> <出力先>
python3 tools/road_graph_build.py <出力先>/roadnet.json <出力先>/metro_osm.json <出力先>/road_graph.sqlite
gzip -9 -c <出力先>/road_graph.sqlite > <営業圏キー>/road_graph.sqlite.gz
```

（道具は route_timer_app リポジトリの `tools/` にあります）

🔴 Overpass は共用の無料サーバーです。**同時に何本も投げない**こと。
